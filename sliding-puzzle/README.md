# Jev 슬라이딩 퍼즐

그림을 5×6(타일 29개 + 빈칸)으로 자르고 섞은 뒤 Jev가 맞춘다. 2026-09-19~20, `jev-latest`(당시 `jev-1.13.0`으로 해석).

Jev는 그림도 보드도 못 본다(`experiments/vision`). 그래서 테트리스와 같은 분업이다: **코드가 보고 Jev가 고른다.** 무엇을 고르게 할지를 세 번 바꿨고, 그 과정이 이 README다. 결론부터:

- Jev는 코드가 써 준 숫자를 **탐욕 탐색과 똑같이** 따른다(3×3 한 칸씩: 1,149/1,151).
- 어떤 숫자가 중요한지는 **스스로 찾아내지 못한다**(5×6 줄 벗기기: 필요한 숫자가 설명에 있어도 동전 던지기, 47%). 지시문에 규칙을 적어 주면 그대로 적용한다(71%).
- 전략(자기를 가두지 않는 순서)은 없다. 코칭해도 없다(5×6 자유 선택: 0/20).

지금 페이지와 영상은 3장 "줄 벗기기"다.

## 3장. 5×6, 어느 줄을 벗길까 (현재 버전)

남은 미해결 영역은 항상 오른쪽 아래 직사각형이다(빈칸의 집이 오른쪽 아래라, 아래나 오른쪽부터 벗기면 그 모서리가 주머니가 된다). 결정마다 Jev가 영역의 **윗줄**과 **왼쪽 열** 중 하나를 고르고, 코드가 그 줄의 타일을 순서대로 집에 보낸다(`Grid.bring_home`: 놓인 타일은 벽, 막히면 가까운 벽을 하나씩 풀어 2~4개까지 같이 추적하는 BFS). 영역 높이가 2면 열만, 너비가 2면 줄만 가능하고, 마지막 2×2는 타일별로 마무리. 5×6 → 2×2까지 줄 3번 + 열 4번, 순서 35가지가 **모두** 60/60 풀린다. 그래서 Jev의 판단은 총 밀기 수에만 나타난다.

`sif.ask()` 하나에 `line` Choice + `progress` Score. 선택지 설명:

```
top row: tiles 8-12 (5), 0 already in place, distance from home total 13, farthest 3, blank 0 from the line
left column: tiles 8-26 (4), 0 already in place, distance from home total 15, farthest 5, blank 4 from the line
```

BFS 비용은 주지 않는다 — 주면 1장처럼 숫자 비교기가 된다. 상태는 판·목표·미해결 영역.

**측정** (`run_peels.py`, 무작위 가해 판 60개, 맨해튼 하한 평균 약 100):

| 조건 | 총 밀기 평균 | 근시안 일치 |
|---|---|---|
| oracle (판마다 35순서 중 최선, 사후) | 295 | |
| myopic (지금 싼 줄, BFS로 계산) | 313 | 1.00 |
| distance (거리 합 작은 줄) | 325 | 0.74* |
| **jev, 규칙 힌트 있음** | **327** | **0.71** |
| cols-first | 335 | |
| random | 336 | |
| jev, 힌트 없음 | 336 | 0.47 |
| rows-first (사람 순서) | 346 | |
| jev, 숫자 없이 | 347 | 0.17 |

- \* 기준선의 근시안 일치는 `results_peels.json`에 없고 같은 60판을 따로 돌려 센 것(거리 평균 0.48, 가장 먼 타일 0.47, 타일 수 0.64, 빈칸 거리 0.24).
- 힌트 없는 Jev는 무작위와 같다(336 vs 336, 근시안 일치 47%). 설명에 `distance from home total`이 있고 그것만 보면 74%인데, 다섯 숫자 중 어느 것이 밀기 수를 정하는지 Jev는 고르지 못한다.
- 지시문에 한 문장을 더하면(`HINTED_INSTRUCTIONS`: "줄의 밀기 수는 대략 타일들의 집까지 거리 합이니 작은 쪽이 보통 싸다") 71%·327로 규칙 기준선에 붙는다. 규칙은 Jev가 찾는 게 아니라 사람이 적어 주는 것이다.
- 숫자를 빼면 무작위보다 나쁘다(347, 17% — 일관되게 반대쪽을 고른다).
- 결정 234~335회, latency 중앙값 256~293ms. 결정 수가 조건마다 다른 건 순서에 따라 선택지가 하나뿐인(묻지 않는) 자리가 달라서.

## 2장. 어느 타일을 집에 보낼까 (실패)

밀기 하나가 아니라 **"다음에 집에 보낼 타일"**을 고르게 하면 Jev에게 판단이 생기지 않을까 해서 해봤다. 코드가 그 타일을 BFS로 집에 보내고 벽으로 고정한다. 선택지 설명은 타일마다 현재 위치·집 위치·거리·같은 줄에 이미 놓인 이웃 수.

**3×3** (`run_targets.py --grid 3x3`, 판 60개): 순서가 중요하다. 사람 순서(윗줄 → 열 두 개 → 2×2) 60/60·최적 대비 1.73, 1→8 60/60·1.82, 가까운 것부터 34/60, 무작위 42/60. **Jev 38/60**(2.06), 숫자 없는 Jev 57/60(2.10) — 실행기가 고른 타일을 벽으로 고정하므로 이 수치에도 실행기 성질이 섞여 있다. 숫자를 주면 가까운 타일을 먼저 고르다가 자기를 가두고, 안 주면 8·5·6 같은 순서로 느리지만 안 갇힌다.

**5×6** (`run_targets.py`, 판 20개): 사람 순서만 20/20이고 **나머지는 전부 0/20** — 1→29 고정 순서(마지막 두 줄에서 주머니 패리티), 가까운 것부터, 무작위, Jev(중앙값 12.5개 놓고 실패), 코칭한 Jev(지시문에 사람 전략을 적어 줌, 14개), 숫자 없는 Jev(21개 — 1, 2, 3, … 번호순이라 고정 순서와 같이 4번째 줄에서 막힘). 벽 사이에 폭 1짜리 복도가 생기면 그 안의 타일은 못 바꾼다(`3×4`로 확인: 주머니 칸의 타일은 영원히 그 타일). 이건 실행기의 성질이라 "Jev가 순서를 못 정한다"는 판정이 되지 않고, 그래서 모든 선택이 실행 가능한 3장으로 문제를 바꿨다.

## 1장. 3×3, 한 칸씩 (v1)

밀기마다 코드가 되돌리기를 뺀 가능한 밀기 1~3개에 `tile 5 slides left. distance 8 (-1), tiles home 3 (+1)` 한 줄씩 붙이고 Jev가 `move` Choice로 고른다(+ `looping` Noul, `progress` Score). `distance`는 맨해튼 + 선형충돌×2. 선택지가 하나면 묻지 않는다. `run_trials.py`, 최단 8·12·16·20수 판 15개씩, 60수 제한.

| 조건 | 푼 판 |
|---|---|
| greedy (같은 숫자, 동률 무작위) | 41/60 |
| greedy (동률 첫 번째) | 36/60 |
| **jev** | **26/60** |
| jev 확률 표본 추출 | 25/60 |
| jev 숫자 없이 | 10/60 |
| random | 0/60 |

Jev는 최저 distance가 갈리는 1,151회 중 1,149회 그걸 골랐다. 남는 차이는 동률(738회)뿐인데 `up`·`left` 편애(up:down 141:26, left:right 137:12)가 결정론이라 빈칸이 2×2를 도는 4주기에 갇힌다. `looping` 뉴런은 진짜였다(재방문 밀기 0.84 vs 새 판 0.60) — 갇힌 걸 알지만 못 나온다. 코드가 6수 미리보기를 계산해 주면 탐욕만으로 58/60이라 그건 넣지 않았다.

문구도 두 번 바꿨다. "본 판이면 조금 나빠도 새 판" 지시 + `seen` 태그 → +1 밀기를 45% 골라 10/60. "되돌리지 마" 지시 → 되돌리기가 유일한 -1이면 무시하고 되돌려 7/60. 되돌리기를 **코드가 선택지에서 빼자** 26/60. 규칙은 지시문이 아니라 후보 열거에 넣어야 한다 — 3장의 힌트 결과와 합치면: 숫자 비교 규칙은 지시문으로도 되고, 금지 규칙은 후보 열거로만 된다.

## 실행

```sh
op run --env-file=sliding-puzzle/.env.tpl -- uv run python sliding-puzzle/server.py   # http://127.0.0.1:3459
```

섞기 → Jev 시작. 결정마다 요청 하나(힌트 있는 지시문; `?hint=0`이면 없이), 줄이 하나뿐이면 묻지 않는다. 벗기는 줄의 타일은 빨간 테두리, 고정된 타일은 어둡게. "그림 바꾸기"로 사진을 넣으면 6:5로 가운데를 자른다. `?demo=1`은 혼자 섞고 풀고, `?slide=<ms>`가 밀기 하나의 시간(기본 85), `?clean=1`은 컨트롤 숨김. 그림은 캔버스로 그린 것이라 저장소에 남의 사진이 없다.

```sh
uv run python sliding-puzzle/run_peels.py --no-jev                  # 3장 기준선, 키 없이
op run ... -- uv run python sliding-puzzle/run_peels.py --boards 60  # → results_peels.json
uv run python sliding-puzzle/run_targets.py [--grid 3x3] --no-jev    # 2장 → results_{5x6,3x3}_tiles.json
uv run python sliding-puzzle/run_trials.py --no-jev                  # 1장 → results.json
```

## 영상

`demo.mp4`(36초, 2560×1440)는 `?demo=1&slide=85`(힌트 있는 지시문, 페이지 기본값)를 `record.mjs`로 찍은 첫 테이크 그대로 — 어느 순서든 풀리므로 고를 게 없다. 298수, 결정 5번(강제 2번), 서버는 `SIF_CACHE=0`. `record.mjs`는 Playwright 헤드리스 `recordVideo`(1x라 뷰포트 2560×1440 + `body.style.zoom = 2`). ESM은 `NODE_PATH`를 무시하므로 `~/.npm/_npx/*/node_modules`를 `node_modules`로 심링크한 폴더에서 돌린다. `record.sh`(bug-hunter 방식 화면 캡처)는 메인 화면이 비어 있을 때만 — 이번엔 다른 세션의 창이 찍혀서 버렸다.

## 한계와 다음

- 3장의 결정은 이진이고 이득은 사후 최선 대비 10% 남짓. Jev가 할 일이 작다. 결정을 키우려면 "어느 방향에서 벗길까"(위/아래/왼/오른, 빈칸 집을 옮기며)처럼 선택지를 늘려야 한다.
- 실행기의 unlock은 가까운 벽부터 최대 4개라 이론상 실패할 수 있는데 35순서×60판에서는 없었다.
- 그림은 장식이다. 번호 없는 그림 조각의 "이 조각이 어디 조각인가"를 이음새 픽셀 차이로 숫자화해 Jev에게 묻는 건 eye 쪽 실험감.
