# ㄱㄴㄷ 선택지를 진술 내용으로 풀어 쓰는 형식 시험 — 실행 전 조건

질문: Jev가 ㄱㄴㄷ 조합형을 틀리는 원인이 입력 형식인가. 기존 입력에서 `criteria`는 `"ㄱ, ㄴ"` 같은 기호뿐이고 진술 본문은 `passage` 끝의 `<보기>`에만 있다. Choice 한 번의 구조와 호출 수는 유지하고 선택지 문자열만 바꾼다.

1. 대상은 `decompose/run_decompose.py`의 `targets()`와 같은 234문항이다. 모든 문항의 선택지 5개가 조합형이다. 결과를 본 뒤 대상을 바꾸지 않는다.
2. 모델 `jev-1.13.0`, Choice 1회, 보기 순서 원래대로(rotation 0). `state`와 `instructions`는 `run_exam.make_job`과 같다. 바뀌는 것은 `criteria`의 각 값뿐이다.
3. 형식(`spelled`): 각 선택지를 `옳은 것: ㄱ. <본문> / ㄴ. <본문> || 옳지 않은 것: ㄷ. <본문>`으로 쓴다. 조합에 든 진술과 빠진 진술을 모두 적는다. 빠진 진술이 없으면 `옳지 않은 것: 없음`이다. 진술 본문은 `<보기>`에서 추출한 문자열 그대로다. `passage`의 `<보기>`는 지우지 않는다.
4. 주 결과: 같은 234문항의 정답 수를 기존 기록(`all_subjects`, 120개)과 비교한다. 좋아진 문항과 나빠진 문항을 모두 센다. 기존 기록과 `prompt_study` 기준선 재실행 사이에서도 26문항의 답이 바뀌었다(맞던 7개가 틀리고 틀리던 9개가 맞음, 120 대 122). 이 변동 폭을 넘지 못하면 형식 효과로 해석하지 않는다.
5. 전송 오류는 같은 요청으로 최대 3회 재시도한다. 결과를 보고 형식을 고치면 새 이름으로 별도 실행한다.
6. LaTeX 표기 정리, `passage`와 `visual_description`의 중복 제거는 이 시험에 섞지 않는다.

## 추가 확인 (2026 결과를 본 뒤, 2025 호출 전에 적음)

7. 2026 결과는 120→133(좋아짐 34, 나빠짐 21, 부호검정 p≈0.10)으로 변동 폭을 넘었지만 확정되지 않았다. 형식을 고치지 않고 2025학년도 검증 자료(`prompt_study/validation_2025/dataset.json`)에서 같은 필터에 걸리는 34문항에 같은 `spelled` 형식을 한 번 호출한다. 비교 대상은 `prompt_study/validation_results`의 기존 `baseline` 기록이다. 34문항은 작으므로 방향 확인으로만 보고한다.
