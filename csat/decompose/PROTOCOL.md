# ㄱㄴㄷ 진술 분해 시험 — 실행 전 조건

질문: Jev가 ㄱㄴㄷ 조합형을 틀리는 이유가 진술 하나하나를 모르기 때문인가, 판정은 맞는데 조합 한 번 고르기에서 실패하기 때문인가.

1. 대상은 2026학년도 884문항 중 선택지 3개 이상이 ㄱㄴㄷ 조합이고 `<보기>`에서 `ㄱ. …` 형식 진술 2~4개를 추출할 수 있는 문항 전체다(234문항, 진술 770개). 모두 "옳은(적절한) 것만 고른" 형식이므로 정답 조합에 든 진술은 참, 빠진 진술은 거짓으로 채점한다. 결과를 본 뒤 대상을 빼거나 더하지 않는다.
2. 모델은 `jev-1.13.0`. 진술 하나당 Noul 한 요청. state는 원래 문항의 state(question·passage·visual_description) 그대로에 `statement` 필드만 더한다. 지시문은 `run_decompose.py`의 `INSTRUCTIONS`로 고정한다. 정답·다른 모델의 답은 넣지 않는다.
3. 조합 규칙(고정): 각 선택지에 대해 Σ_{포함} log p + Σ_{제외} log(1−p)를 계산해 최대인 선택지를 답으로 한다(p는 0.001~0.999로 자른다). 선택지에 없는 조합은 고르지 않는다.
4. 주 결과: 같은 234문항에서 (a) 기존 단일 Choice 정답률(`all_subjects` 기록) 대 (b) 분해·조합 정답률. 보조: 진술 단위 정답률(p≥0.5를 참으로), 기존 오답을 "진술 판정이 모두 맞았는데 조합이 틀림"과 "진술 판정 중 하나 이상이 틀림"으로 나눈 수.
5. 호출 수는 문항당 2~4배이므로 비용·지연이 다른 구조다. 같은 조건의 개선으로 비교하지 않고, 원인 분리용 진단으로 해석한다.
6. 전송 오류는 같은 요청으로 최대 3회 재시도한다. 결과를 보고 지시문을 바꾸지 않는다. 바꾸게 되면 새 이름으로 별도 실행한다.
7. 그림 설명 전사 오류가 섞여 있을 수 있다(`prompt_study/input_audit`). 두 방식이 같은 입력을 받으므로 비교에는 영향이 같지만, 절대 정확도는 확정치가 아니다.
