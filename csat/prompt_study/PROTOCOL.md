# Jev 단일 호출 프롬프트 개선 시험 — 실행 전 조건

1. Jev `jev-1.13.0`을 고정한다. 각 문제·각 조건은 Choice 한 개, 한 요청이다. 지문·그림 전사·보기·보기 순서를 바꾸지 않는다. 정답·해설·예시 정답은 입력하지 않는다.
2. 개발 자료는 기존 2026학년도 884문항 전체다. 이 자료의 결과는 이미 분석했으므로 새 검증 자료라고 부르지 않는다. 기존 프롬프트도 새로 호출하여 시점 변동을 대조한다.
3. 후보는 `direct_ko`, `structured_ko`, `structured_en` 세 가지다. 기존 범용 문구는 `baseline`이다. `prompts.py`를 호출 전에 고정하고 해시를 보존한다. 유형별 분기는 문항·보기·과목만 읽는 고정 코드이며 정답/과거 성패는 참조하지 않는다.
4. 개발 정확도가 가장 높은 비기준선 후보 하나를 선택한다. 동률이면 입력 토큰이 적은 후보, 다시 동률이면 위 후보 목록 순서를 따른다. 이후 프롬프트를 수정하지 않는다. 개발에서 기존 문구보다 낫지 않더라도 최고 후보 하나를 검증해 음성 결과를 숨기지 않는다.
5. 별도 검증은 2025학년도 영어 독해 18~45번 28문항, 한국사·생활과 윤리·정치와 법·물리학Ⅰ·화학Ⅰ 각 20문항, 합계 128문항이다. 과목과 범위는 개발 결과를 보기 전에 고정했다. 이 6과목 결과를 전과목 개선으로 일반화하지 않는다.
6. 새 회차도 같은 텍스트 변환 조건을 사용한다. 전사·원문 검수에는 정답을 보내지 않는다. 입력의 누락·원문 불일치만 수정하며 풀이 모델의 답을 보고 문제 표현을 고치지 않는다.
7. 검증에서는 기준선과 선택된 후보만 각각 한 번 호출한다. 좋아진 문제와 나빠진 문제를 모두 집계한다. 차이의 불확실성은 동일 원문 페이지의 문항을 묶은 bootstrap 구간으로 보조 보고한다. 원래 배치의 단순 정답 수 차이가 주 결과다.
8. ㄱ·ㄴ·ㄷ를 별도 API 질문으로 분해하거나, 상위 2개를 다시 물어보거나, 다른 모델/코드가 풀이하는 방식은 이번 비교에 포함하지 않는다. 비용·지연·호출 수가 달라지는 구조 변경은 별도 실험이다.
9. 공개 기출의 학습 포함 여부와 텍스트 전사의 잔여 오류는 확인하기 어렵다. 결과는 이 고정된 입력과 회차에 대한 관측이다.
