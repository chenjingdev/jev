## SemIf (구 openjev) — https://github.com/TheoLeeCJ/SemIf

**특징**
- "3090 한 장으로 집에서 Jev 비슷한 걸 돌릴 수 있나"가 질문. 학습 없음, 공개 GGUF 모델의 logit을 바로 읽는다.
- 브라우저에서도 돈다(WebGPU). "어떤 회사는 대기열에 넣지만 SemIf는 오늘 브라우저에서 돈다"는 짤이 README에 있다.
- 벤치마크 fixture, 원시 타이밍, 행 단위 예측, 체크섬을 전부 `results/raw/`에 커밋. 재현성 면에서 가장 성실하다.

**속도** (RTX 3090, Qwen3.5-4B Q4_K_M)
| 경로 | 수치 |
|---|---|
| 판단 1건, 21개 기준 직접 logit | 1.023 s, 출력 토큰 0 |
| 같은 것을 JSON 배열 생성 | 5.332 s, 출력 토큰 111 (첫 토큰 0.489 s) |
| 777판단(37상태×21기준) fresh | 2.33/s, 333 s |
| 〃 serial prefix reuse | 10.75/s, 72 s |
| 〃 parallel suffixes | 20.03/s, 38.8 s |
| 〃 Qwen3-Reranker-4B | 1.86/s, 417 s |

빠른 경로는 실험적이며 BF16으로 바꾸면 777건 중 5~6건의 argmax가 달라진다고 스스로 밝힌다.

**성능**
| 모델 | 용량 | 자체 케이스 balanced acc | 교란 케이스 | TypeSafe 부분집합 agreement |
|---|---:|---:|---:|---:|
| Qwen3-0.6B Q8 | 639 MB | 0.440 | 0.528 | 0.407 |
| MiniCPM5-2B Q4 | 1.56 GB | 0.686 | 0.693 | 0.637 |
| Qwen3.5-4B Q4 | 3.01 GB | 0.813 | 0.766 | 0.845 |
| Jev(공개 서비스) | — | — | — | 0.883 |

WANLI(NLI) 256행에서는 0.637로 뚝 떨어진다. 같은 4B를 reranker로 쓰면 전부 크게 나빠진다(0.625 / 0.522 / 0.560) — 판단은 유사도 검색이 아니라는 증거.

**후기**
- 커뮤니티: 나흘 만에 1.6k 스타, 포크 103. 이슈는 exl3 양자화 브리지, MLX 네이티브, MPS/CPU 지원 등 "내 하드웨어에서 돌리게 해 달라"가 대부분. "더 큰 모델, 더 많은 태스크"(#7) 요청도 있음.
- 내 평가: 0.6B는 쓸 수 없고(0.44, 동전 던지기 수준) 4B부터 쓸 만하다. 판단 1건에 1초는 우리 `sif`가 쓰는 Jev(200ms 왕복)보다 5배 느리고, 병렬로 묶어야 20/s가 나온다. 확률은 보정 안 됨. "Jev를 대신한다"기보다 "Jev가 왜 빠른지 구조를 보여 주는" 교재로 가치가 있다.

## NanoJev — https://github.com/TianyuCodings/NanoJev

**특징**
- Qwen3-0.6B에 판단 헤드를 붙이고 직접 학습. 후보 2~255개 동적, 한 forward에 18질문·6상태·44경로.
- 데이터 생성 → 학습 → 평가 → 체크포인트까지 파이프라인 전부 공개. HF `C-Tianyu/NanoJev`에 variant별 체크포인트(`local_atomic_seed17`, `games_gold_seed17`, `events_*_seed17`).
- 평가가 게임(미로, 스네이크)과 안전 판단이라 Jev 발표 데모와 직접 비교한다.

**속도**: README에 지연 시간 수치 없음. 0.6B라 빠를 수밖에 없지만 측정치는 없다.

**성능**
| 과제 | NanoJev | Jev | 학습 전 Qwen3-0.6B |
|---|---|---|---|
| 미로 50×50 | 244회 시도, 충돌 36, 도달 | 2,738회, 충돌 1,044, 도달 | 171회, 충돌 43, 도달 |
| 스네이크 256스텝 | 먹이 27, 생존 | 먹이 30, 생존 | 먹이 25, 갇힘 |
| 내비게이션 4×4 / 6×6 OOD | 95% / 90% | 100% / 95% | 35% / 15% |
| 안전 판단 test / 50×50 OOD | 77.84% / 76.56% | — | — |

미로에서 Jev가 시도 2,738회로 훨씬 많은 것은 흥미롭지만, 컨트롤러 코드가 같다고 해도 프롬프트 형식이 Jev에 불리했을 수 있어 그대로 믿기는 어렵다.

**후기**
- 커뮤니티: 384 스타, 포크 35. 학습 계열 중 압도적 1위.
- 내 평가: "0.6B도 좁은 과제에 맞춰 학습하면 Jev 근처까지 간다"는 것을 보여 주는 게 핵심. 대신 범용성 평가(TypeSafe eval)는 없다. 우리가 한국어 판단 모델을 학습해 본다면 파이프라인 구조는 여기서 빌려올 만하다.

## system-one-open — https://github.com/mithalouni/system-one-open

**특징**
- 범용을 노린 유일한 학습 복제본. HF 공개 판단 데이터셋 92개 + 규칙 기반 합성 7종으로 Gemma 4 E2B(attention LoRA)와 Gemma 3 270M을 CE + Brier로 학습, temperature scaling.
- TypeSafe 발표 데모 8개(터미널 레이스, 이메일 분류, Doom, browser-use, 자율주행 시뮬, 스마트홈…)를 하나씩 재현. Mario는 베이스 모델이 가만히 서 있어서(noop 77%) 뺐다고 정직하게 적음.
- Modal에 배포된 FastAPI. 가중치는 Modal 볼륨에만 있고 HF 업로드 예정.

**속도**
| 항목 | Jev | 복제본 |
|---|---|---|
| 발표 데모 27질문 1콜 | 114 ms | 97 ms (H100) |
| 이메일 1,000통 × 4판단 | — | 13.4 s, 74.6통/s |

**성능**
| 항목 | Jev | 복제본(E2B) |
|---|---|---|
| TypeSafe 공개 eval 공통 343쌍 | 86.9% | 76.7% |
| 같은 eval, 학습 안 한 Qwen 7B(jev-on-a-laptop) | — | 73.8% |
| 합성 데모 과제 7종 | — | 98.8%, ECE 0.003 |
| held-out 과제 유형(학습 안 함) | — | 74.8% |
| 스팸 분류 | — | 95.4% |

**후기**
- 커뮤니티: 스타 4. 가장 중요한 저장소인데 거의 안 알려져 있다(브라우저 데모가 없고 Modal 계정이 필요해서인 듯).
- 내 평가: 숫자가 가장 솔직하다. 학습 안 한 Qwen 7B가 73.8%인데 학습한 E2B가 76.7%면, **지도학습이 주는 이득이 3점뿐**이고 Jev와의 10점 차이는 데이터나 RLCD에서 온다는 뜻이다. 합성 과제 98.8%와 held-out 74.8%의 차이는 학습 분포 밖으로 나가면 바로 무너진다는 뜻. 직접 만들려면 이 레시피에서 출발하되 한계도 여기서 배운다.

## jevfire — https://github.com/kikoncuo/jevfire

**특징**
- 학습 없음. vLLM 위에서 공유 prefix + 필드별 접미로 1~64필드, 필드당 최대 255선택지를 한 번에 채점. 라벨이 단일 토큰인지 검증.
- 필드끼리 독립 채점이라 "앞 값이 뒷 값을 조건 짓는" 스키마는 못 한다고 명시. 확률은 상대 선호이지 보정 확신도가 아니라고도 명시.
- 브라우저 데모(WebLLM, Qwen3.5-0.8B)로 Mario 클리어.

**속도** (Qwen3.8-27B-FP8, RTX PRO 6000 Blackwell, vLLM 0.29)
| 워크로드 | 제약 JSON 생성 | jevfire | 배율 |
|---|---:|---:|---:|
| 4필드 fresh | 877.5 ms | 109.9 ms | 7.98× |
| 12필드 fresh | 2,239.4 ms | 330.1 ms | 6.78× |
| 28필드 fresh | 5,113.1 ms | 496.9 ms | 10.29× |
| 28필드 warm prefix | 5,112.8 ms | 346.3 ms | 14.77× |
| 긴 컨텍스트 12필드 fresh | 2,951.1 ms | 1,060.8 ms | 2.78× |

aligned prefill로 긴 컨텍스트 12필드 2,167 → 255 ms. Mario는 M4 Max에서 판단당 71 ms, 12.7판단/s.

**성능**: 정확도 벤치마크 없음. 시스템 성능(지연) 논문이지 판단 품질 논문이 아니다.

**후기**
- 커뮤니티: 스타 5.
- 내 평가: 27B를 500ms 안에 28판단 돌리는 건 인상적이고, "vLLM prefix cache만으로 어디까지 가나"의 상한선을 보여 준다. 긴 컨텍스트에서 배율이 2.8×로 떨어지는 것이 정직한 한계. 품질 측정이 없어서 sif 백엔드로 바로 쓰기는 어렵다.

## Verdict-open-jev — https://github.com/Heman10x-NGU/Verdict-open-jev

**특징**
- 유일한 인코더 접근. ModernBERT-base 151M + GLiClass 방식 bi-encoder 헤드. 후보 슬롯 25(기권 `__insufficient_evidence__` 1 포함).
- 손실 CE + 1.0·Brier, 후처리 L-BFGS temperature scaling. 체크포인트 선택은 validation NLL.
- WebGPU 브라우저 플레이그라운드, HF `heman10x/rlcd-modernbert-151m`. 용도로 "코딩 에이전트의 MCP 툴 선택"을 든다.

**속도**: forward 1회 35 ms 미만(환경 미기재). 6개 중 가장 가볍다.

**성능** (Banking77 held-out 1,000건)
| 지표 | 보정 전 | 보정 후 |
|---|---:|---:|
| Top-1 | 95.00% | 95.00% |
| Brier | 0.0756 | 0.0785 |
| ECE(10빈) | 1.13% | 3.35% |
| 기권 recall / precision | 97.5% / 89.5% | 〃 |

후보 수를 늘리면 급락: K=3 97% → K=9 91% → K=17 78% → K=25 72%.

**후기**
- 커뮤니티: 스타 6.
- 내 평가: temperature scaling을 했더니 ECE가 1.13 → 3.35%로 **나빠졌다**. 요약기가 틀린 게 아니라 원문이 그렇다. 체크포인트를 NLL로 골랐으니 이미 보정돼 있었고 후처리가 오히려 해쳤다는 뜻인데, 저자가 이걸 문제 삼지 않고 넘어간다. 도메인 하나(은행 의도 77개)에 후보 25개 상한이라 범용 Jev와는 다른 물건. 표에 Jev를 "ECE 0.144, 68%"로 적어 두었는데 무슨 평가인지 불명확해서 무시하는 게 맞다. 다만 "작은 인코더 + 기권 후보"는 저지연 라우팅 용도로 참고할 만하다.

## qwen-rlcd — https://github.com/shamazharikh/qwen-rlcd

**특징**
- Qwen3.5-0.8B-Base(Gated DeltaNet 18층 + attention 6층 하이브리드)에서 **prefix fork** 실행 구현. 순환층은 tree attention mask로 가지를 격리할 수 없으므로 상태를 prefill한 뒤 cache를 배치로 복사한다.
- RLCD를 "정답 있는 질문 위에서 log score/Brier를 보상으로 쓰는 RL"로 해석하고 RLHF의 아첨과 대비. 설계 문서(`PLAN.md`)가 본체.
- M0(추론 동등성)까지만 구현. 템플릿·API는 M1, 학습은 M2로 예정.

**속도**: 수치 없음. Mac CPU fp32 개발, Colab T4는 커널 컴파일 OOM.

**성능**: 과제 정확도 없음. fork vs 순차 실행 오차 4.8e-5(허용 1e-3), 음성 대조군은 6.3/3.1로 크게 어긋나 검증이 의미 있음.

**후기**
- 커뮤니티: 스타 1.
- 내 평가: 결과물이 아니라 설계 노트. 그래도 "하이브리드 아키텍처에서는 왜 tree mask가 안 되나"와 "RLCD를 proper scoring rule로 읽는다"는 두 논점은 다른 데서 못 본 것이라 읽을 가치가 있다. 학습이 실제로 돌면 다시 볼 것.
