# Jev 한계 탐색 실험

`sif.decide()`(Jev Choice, `jev-1.13.0`)를 다섯 방향으로 밀어붙여 무너지는 지점을 찾은 실험. 2026-09-18.

## 설계

한국어 고객 문의 도메인. 정답 가능 카테고리 80개(1~20은 branches 실험과 동일) + 다른 도메인(은행·병원·통신사·SaaS·공공기관·항공·보험·교육) 방해 갈래 175개 = 선택지 255개(문서상 최대).

| 축 | 내용 | 호출 |
|---|---|---|
| width | N ∈ {20, 40, 60, 80, 150, 255}, 문장 160 | 720 |
| neighbors | 단어 하나로 구분되는 가족 8 × 카테고리 4 × 문장 3. 가족 안 4갈래 / 전체 80갈래 | 192 |
| ambiguous | 두 범주에 걸친 문장 40, 기대 분배 부여, 캐시 끄고 3회 | 120 |
| length | 문의를 1k/4k/12k/24k 토큰 약관·FAQ 텍스트에 묻음. 24k에서 앞·중간·끝 | 120 |
| traps | 부정·인용·가정·감정 과잉·영어 이모지 각 10문장. 20갈래 / 80갈래 | 100 |

모든 호출은 질문 1개 단독 `decide`. 1,252호출, 입력 4,621,243 + 출력 1,216,964 토큰, 359초, $0.25, 오류 0.

## 결과 한 줄

1,252건 중 오답 1건. 255갈래도, 19k 토큰 문서 속 문의도, 함정 문장도 무너뜨리지 못했다.

- width: 720/720. 255갈래에서도 방해 갈래가 선택된 적 0회. 정답 확률 최솟값은 N=80부터 0.6대로 내려오고 1.00 미만 건수가 N에 비례해 늘어남(20에서 1건, 255에서 28건)
- width 비용: 요청당 입력 토큰 861(N=20) → 6,883(N=255). latency 중앙값 255 → 290ms
- neighbors: 가족 안 96/96, 전체 80갈래 95/96. 유일한 오답은 "로그인 화면에서 계속 튕겨요" → 앱 오류 신고 0.63 / 로그인 오류 0.37. 데이터셋 경계가 애매한 문장
- ambiguous: 여기가 진짜 흔들린 곳. top2 집합이 기대와 일치한 비율 89/120, top1 확률 평균 0.835, 기대 분배와 절대 오차 0.31. 기대한 두 번째 범주에 0.00을 준 호출 30/120. 3회 반복에서 top1이 뒤집힌 문장 1/40
- length: 120/120, 확률 전부 1.00. 19k 토큰(실측) state도 통과. 32k 상한에는 닿지 않음
- traps: 100/100. 80갈래에서 가정형이 가장 약함(0.980)

## 해석

Jev는 "정답이 하나인 입력"에서는 갈래 수·문서 길이·표면 함정에 거의 무관하게 맞춘다.
약한 곳은 입력 자체가 두 범주에 걸칠 때의 확률 분배다. 확률이 소수 둘째 자리로 반올림되고 분포가 1.00으로 쏠리는 경향이 있어서,
"애매함의 정도"를 확률에서 읽으려면 별도 보정이 필요하다.

## 실행

```sh
uv run python experiments/limits/run.py --dry-run
op run --env-file=<(echo 'TYPESAFE_API_KEY="op://Agent/typesafe jev key/credential"') \
  -- uv run python experiments/limits/run.py
uv run python experiments/limits/report.py
```

주의: sif 캐시 키가 선택지 순서를 무시하므로 반복 측정은 `cache=False`. branches 실험과 문장·선택지가 완전히 같은 호출은 디스크 캐시를 맞는다.
토큰 추정기는 실측보다 약 12% 높게 잡았다(긴 옵션 목록과 약관 텍스트는 더 촘촘하게 토큰화됨).
