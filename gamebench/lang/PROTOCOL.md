# 언어 시험 — 실행 전 조건 (2026-09-28)

질문: 판단 벤치마크 v1에서 Jev-like들이 낮게 나온 것 중 **입력이 한국어라서** 생긴 몫은 얼마인가. Kev와 CLM은 모델 카드의 언어가 영어뿐이라 이 몫이 가장 클 수 있다. 같은 문항을 영어로 옮겨 같은 방식으로 돌리고, 한국어 결과와 문항끼리 비교한다.

## 1. 표본

1. v1 `items.jsonl`에서 게임마다 6문항, 모두 180문항을 뽑는다(`sample.py`, 시드 20260928). 단계 ①②③④를 차례로 돌며 한 문항씩 뽑고, 단계 안에서는 `sha256(시드:id)` 순서를 쓴다. 정답 파일은 읽지 않는다. 결과는 `set/ko.jsonl`이다.
2. 한국어 쪽은 새로 부르지 않고 v1 호출 기록(`results/v1/`)을 쓴다. 문항 내용이 같으면 요청 해시도 같으므로 채점기가 그 기록을 그대로 찾는다.

## 2. 번역

3. 번역하는 것은 한글이 든 문자열뿐이다: `state`의 값, `question`, 보기. 한글이 없는 문자열(판, 좌표, X/O, 숫자)은 그대로 둔다. `state`의 키는 규칙→`rules`, 상황→`situation`, 표기→`notation`, 판→`board`, 덱→`deck`으로 바꾼다.
4. 번역은 에이전트가 게임 묶음별로 한다. 번역자는 정답 파일을 보지 않고, 문항을 풀지 않는다.
   - 원문에 충실하게 옮긴다. 설명을 덧붙이거나, 애매한 곳을 풀어 주거나, 문장을 빼지 않는다.
   - 숫자, 좌표, 기호, 줄바꿈, 문장 구조를 유지한다.
   - 한 게임 안에서 같은 한국어 용어는 같은 영어로 옮긴다.
   - 뜻이 같은 영어 낱말이 있는 게임 용어는 그 낱말로 옮긴다. 묵·찌·빠는 rock·scissors·paper, 포켓몬 타입과 포커 족보는 공식 영어 이름을 쓴다. 한국어 사용자가 가진 사전 지식을 영어 쪽에도 똑같이 남기기 위해서다.
   - 영어 낱말이 없는 용어(윷놀이의 도·개·걸·윷·모 등)만 로마자로 옮긴다. 이런 용어는 한국어 쪽에만 사전 지식이 있으므로 README에 따로 적는다.
   - 짝 문항의 규칙 문구는 한두 낱말만 다르다(예: "이긴 손"과 "진 손"). 번역도 그 자리만 다르고 나머지는 같은 문장이어야 한다.
5. 번역 뒤 기계 검사를 통과해야 한다.
   - 영어본에 한글이 남지 않는다.
   - 문자열마다 숫자 목록(등장 순서 무시)이 원문과 같다.
   - 좌표 표기(`A1`, `D3` 같은 영문자+숫자)가 원문과 같다.
   - 문항마다 보기 수와 순서가 같고, 영어 보기끼리 서로 다르다.
6. 번역자와 다른 에이전트가 원문과 번역을 한 쌍씩 대조해 뜻이 달라진 곳을 표시한다. 검토자도 정답을 보지 않는다. 지적마다 고치거나 고치지 않은 이유를 `translation/review.json`에 남긴다.
7. 검사와 검토를 마친 영어본을 `set/en.jsonl`로 고정하고 sha256을 `set/manifest.json`에 적는다. **모델을 부르기 전에 고정한다.** 결과를 본 뒤 번역 오류를 찾으면 고치지 않고 README에 적는다. 고친 판은 새 태그로 따로 돌린다.

## 3. 실행

8. 7개 시스템 모두 v1과 같은 어댑터, 같은 보기 순환(min(n, 5)), 같은 설정으로 `set/en.jsonl`을 돌린다. 태그는 `lang-en`이다.
9. shim이 모델 입력에 넣는 고정 문구(SemIf·jevmlx·open-jev의 영어 지시문, Laya의 "choice question:")는 바꾸지 않는다. 언어별로 문구를 다듬지 않는다.
10. Jev는 API라 같은 요청에도 답이 조금씩 바뀐다. 이 변동의 크기를 재려고 Jev만 한국어 180문항을 한 번 더 돌린다(태그 `lang-ko-rerun`). 로컬 모델은 결정적이라 다시 돌리지 않는다.

## 4. 분석 (사전 고정)

11. 시스템마다 180문항에서 v1과 같은 방식으로 점수를 낸다. 문항별 우연 보정 점수를 게임 안에서 평균하고, 게임 30개를 똑같은 가중으로 평균한다.
12. **주 지표는 Δ = 영어 점수 − 한국어 점수**다. 95% 구간은 게임 단위 짝 bootstrap(1만 회, 시드 20260928)으로 구한다. 같은 게임 세트를 두 언어에 함께 재표집한다.
13. 해석 규칙은 다음과 같다.
    - Δ 구간이 0보다 위이면 "이 표본에서 한국어가 그 모델의 점수를 낮췄다"고 적는다.
    - 구간이 0을 포함하면 "차이를 확인하지 못했다"고 적는다. 효과가 없다고 적지 않는다.
    - Jev의 Δ를 함께 본다. 번역이 문항을 쉽게 또는 어렵게 바꿨다면 모든 시스템이 같은 방향으로 움직인다. 그래서 각 모델의 Δ − Jev의 Δ도 보고한다.
    - Jev의 Δ는 10번 재실행 변동(한국어끼리의 차이)과 비교해 읽는다.
14. 부 지표도 보고한다. 문항 단위 McNemar(영어 대 한국어 정오), 언어별 순위, 처리 못 한 문항 수(Laya는 보기 48토큰 상한이 언어에 따라 달라진다), ECE, 보기 순서를 바꿔도 같은 답을 고른 비율.
15. 180문항은 게임당 6문항이라 게임 하나의 Δ는 흔들림이 크다. 게임별 Δ는 참고로만 싣는다. 이 결과로 v1 전체 점수를 "영어였다면"으로 고쳐 쓰지 않는다.
